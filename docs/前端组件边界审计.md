# 2. Repeated UI Pattern Audit

## 2.1 MovieCard：存在统一核心，但完整交互尚未统一

最直接的证据是 [library-mock.js](E:/AI-Media-Center/html/assets/js/personal-cinema-library-mock.js:597) 的 `renderMovieCard()`，以及 [movie-card.css](E:/AI-Media-Center/html/assets/css/personal-cinema-movie-card.css:1)。

普通卡片的语义结构是：

> 单部本人片库电影 → 海报与详情入口 → 播放／更多 → 片名 → 年份与类型。

| 对象 | 结构、尺寸和行为 | 判断 |
|---|---|---|
| 主片库、最近添加、收藏、未看、已看 | 同一生成器、同一 CSS、同一交互脚本；2:3 海报、10px 圆角；13px 标题、12px 元信息；30px 播放／更多 | **完全相同的 MovieCard 实现族** |
| 首页最近添加、未看 | 同一生成器和海报共享 CSS；宽度由 Shelf 分配 | 同一个 MovieCard 候选；焦点、触摸和菜单存在历史差异 |
| 合集详情的成员电影 | 同一生成器；同类播放／更多和个人状态动作 | 同一个 MovieCard；不是 CollectionCard |
| 电影详情系列区域 | 同一生成器，类名改为 `.series-card`；当前电影加 outline | 同一个 MovieCard，增加当前上下文状态 |
| AI 起始卡、相近候选卡 | 手写生成器，但海报、文字、播放／更多结构基本相同 | 普通卡可以复用；条件差异说明留在外围 |
| 来源详情的电影 | 同一生成器，动作结构相同 | 卡片核心可复用；菜单动作集和触摸实现需单独确认 |
| 来源列表最近入库 | 整体 `<a>`；没有播放／更多；元信息为来源名 | 入库预览卡，不应强制补齐普通卡动作 |
| 扫描结果 | 整体 `<a>`；没有播放／更多；元信息为年份／质量 | 与来源最近入库同属预览卡族 |
| 首页最近观看 | 16:9；标题状态叠在图内；按钮位置不同 | 独立 `ContinueWatchingCard` |
| 主片库合集卡 | Collection ID、合集标题、成员数；进入合集，无合集播放／收藏／观看状态 | 独立 `CollectionCard` |
| AI 推荐结果 | 左海报、右标题事实与推荐理由、独立动作行；hover 仅作用于海报区域 | 独立 `RecommendationCard` |
| 识别候选 | 待确认 TMDB 候选、单选、置信度／文件匹配语义 | 独立匹配领域 UI，不是 MovieCard |
| 全局搜索结果 | 40px 缩略海报、横向文本、活动项、确认导航 | 搜索结果行，不是 compact MovieCard |

**“使用相同生成器”证明结构复用，不证明完整交互已经一致。** 首页、详情、AI、来源详情的菜单和焦点处理仍由不同脚本负责。

## 2.2 Shelf 与 Grid

| 区域 | 实际布局和行为 | 边界判断 |
|---|---|---|
| 首页四组内容架 | `display:flex`、横向 overflow、无 snap；普通纵向 wheel 映射横滚，边界仍消费事件 | 存在真实的页面内滚动容器复用 |
| 详情演职员 | 横向 CSS Grid、96px 列、18px gap、proximity snap、溢出箭头 | 不与首页强行合并 |
| 详情系列电影 | 横向 Flex、20px gap、proximity snap、溢出箭头 | 与演职员共享滚动控制意图，但内容布局不同 |
| AI `.ai-starter-shelf` | `flex-wrap:wrap; overflow:hidden` | **实际上是换行布局，不是横向 Shelf** |
| 扫描 `.poster-strip` | `display:grid`，运行和完成状态改变列宽 | **不是横向 Shelf** |
| 片库／来源／合集成员网格 | CSS Grid，列宽和断点按页面不同 | 普通 CSS 布局即可 |

因此：

- **现在不建议创建覆盖全站的 `MediaShelf.vue` 或 `MovieShelf.vue`。**
- 首页开发时，可抽一个页面范围的 `HomeShelf.vue`，服务四组真实重复的横滚行为。
- 详情页以后再判断是否需要自己的 Shelf 控制组件，不提前给首页容器塞 `snap`、箭头、人员模式等开关。
- **不建议现在创建 `MovieGrid.vue`。** 它暂时没有超出 CSS 布局的独立职责。

首页 Shelf 应负责：

- 横向布局、gap、overflow 和容器宽度。
- 保留不同内容架已有的 item width 规则。
- wheel 单位处理、边界消费、Ctrl／Shift 与原生横滚豁免。
- 键盘可达、聚焦内容可见、减少动效。

它不负责 Movie 查询、排序、收藏、播放、组标题或“查看全部”。这些由页面与内部卡片负责。

## 2.3 其他重复模式

| 候选族 | 审计结果 |
|---|---|
| 筛选／排序 | 五个片库页面的工具条 DOM **逐字一致**，共享脚本；应作为一个 `LibraryToolbar`，暂不拆多个小组件 |
| 全局搜索 | 13 个实际页面都有同一搜索任务与主体结构；应归 Shell 单实例 |

| 空状态 | 片库空状态可在片库功能域复用；来源、AI、匹配的空状态结构和恢复动作不同 |
| Skeleton | 五个片库页共享电影骨架；首页搜索骨架是另一种结构 |

| Dialog | 搜索、来源编辑、匹配确认共享部分模态行为，但尺寸、滚动组织和内容职责不同 |
| Toast／StatusMessage | 多数原型只有隐藏 live region 或局部反馈；没有全站统一可见 Toast 的原型证据 |

## 4.1 MovieCard.vue

| 项目 | 建议 |
|---|---|
| Type | **A — Global Shared Component** |
| Suggested Path | `frontend/src/components/media/MovieCard.vue` |
| Responsibility | 单部电影的完整浏览单元：海报、片名、年份／类型、详情入口、播放和更多触发器；图片异常、焦点、触摸和按钮状态 |
| Not Responsible For | 查询／排序／分页、个人片库归属判断、收藏持久化、调用播放器、资源版本选择、生成推荐理由、所属 Shelf／Grid |
| Reused By | 首页最近添加／未看；五个片库页；合集成员；电影详情系列；AI 普通海报卡；来源详情卡片核心 |
| Visual Source | 五个片库页面及共享 movie-card/library-view CSS；首页普通卡；详情 `.series-card`；AI 普通卡；来源详情实际级联 |
| Shared Interaction | 不缩放海报；只改变 Scrim 与控制显隐；独立点击区域；键盘可达；展开态保持更多按钮可见；图片失败保留详情和操作 |
| Minimal Props | `movie: { id, title, poster, year, genreLabel, watchStatus }`；`detailTo`；菜单关联所需 `menuId`、`menuOpen`。真实播放状态接入时再加入最小的不可播放／请求中信息 |
| Emits | `play(movieId)`；`more({ movieId, trigger })` |
| Variant | **No variant needed yet.** |

补充边界：

- `genreLabel` 表达当前需要展示的类型，不能未经核对就把所有页面改成 `genres[0]`。
- 卡片宽度由父布局分配；首页较宽、AI 较窄不构成 `large/compact` variant。
- `favorite` 主要由菜单消费；不必为了复制原型 `data-*`，让卡片接收整份 Movie DTO。
- 详情系列的 `current` 是当前上下文状态，迁移详情时再加入，不等于多选，也不是新 variant。
- 不自动新增收藏角标、质量徽章、进度条；原型没有显示的内容不能因通用规范示例直接补上。

**play / more / detail 的归属：**

| 操作 | 负责方 |
|---|---|
| 播放按钮的反馈与事件 | MovieCard |
| 获取播放信息、调用 mpv、处理结果 | 上层用例，经既有数据访问边界 |
| 更多触发器及其可访问状态 | MovieCard |
| 菜单定位、键盘、关闭和焦点归还 | MovieContextMenu |
| 详情链接的呈现与原生导航语义 | MovieCard，使用上层提供的 `detailTo` |
| 详情路由定义 | Router |
| 收藏／观看状态更新、列表成员变化 | 上层用例；成功状态回传组件 |

使用真实链接后，**不需要再同时 emit 一个导致第二次导航的 `detail` 事件**。播放和更多必须是与链接并列的动作，不能嵌套进整卡链接。

| Minimal Props | `open`、`anchor`、`movieId`、`title`、`favorite`、`watchStatus`；需要时传入当前动作的 busy／disabled 状态 |
| Emits | `close(reason)`、`play(id)`、`detail(id)`、`favoriteChange(id, next)`、`watchStatusChange(id, next)`、`versions(id)` |
| Variant | 目前不新增业务 variant。桌面浮层／窄屏操作面板是响应式呈现；跨页面策略仍需确认 |

应作为独立公共组件，**不要把菜单 DOM 和全套监听复制进每张 MovieCard**。首阶段可由页面持有一个活动菜单实例，卡片只提供电影身份和触发锚点。

它也不应一开始就升级成万能 `ContextMenu` 框架。电影菜单有真实稳定的动作语义，来源菜单和账号菜单不能仅因都是 `role="menu"` 就一起重构。

统一行为要求：

- 打开时记录实际触发器；键盘打开后将焦点放到可操作项。
- Up／Down 移动，Home／End 定位首尾，Enter／Space 激活。
- `Shift+F10`／菜单键可从影片入口打开。
- Escape 只关闭当前顶层；返回有效触发器。
- 非模态菜单 Tab 关闭后正常继续导航；模态底部面板应匹配其焦点约束。
- 外部点击不抢走用户刚点击的新目标焦点。
- 导航或状态更新删除卡片时，不能强行 focus 已卸载元素。
- 菜单翻转／限制位置，不能被 Shelf overflow 裁掉。
- 无关收藏状态、键盘活动项、hover、pressed 分开表达。
- Motion 按 DESIGN：可中断，不等待动画才响应；减少动效去掉位移。

`PageContainer`、纯 `MovieGrid`、静态 Section wrapper、MovieTitle、MovieMeta、PosterOverlay、PlayCircle、MoreButton、独立 Scrim。

这些内容先保留为所属语义组件内部结构或共享 CSS。

# 7. Variants

**本轮没有足够理由新增 MovieCard 的 `standard/compact/large` variant。**

| 差异 | 正确归类 | 理由 |
|---|---|---|
| 首页卡宽、片库卡宽、AI 起始卡宽 | 父布局尺寸 | 没有改变电影卡身份和动作 |
| `.series-card.current` | 当前上下文状态 | 当前影片身份，不是另一套卡片 |
| favorite、watched、watching | 数据状态 | 不改变结构，不是 variant |
| AI 相近候选下方条件差异 | 外部说明区域 | 推荐约束不属于基础 MovieCard |
| 最近观看与普通卡 | 不同组件 | 图像比例、文本布局、控制位置和观看语义都不同 |
| Collection 与 Movie | 不同组件 | 对象身份、可用动作与状态归属不同 |
| 入库预览与可操作电影卡 | 不同组件 | 全卡导航与多动作结构不同；两类均有真实复用 |
| AI 推荐横向条目 | 不同组件 | 推荐事实、解释及动作行形成完整语义 |
| 来源表单添加／编辑 | 同一组件的真实模式 | 当前原型已共用表单，字段初始化与提交含义不同 |
| 菜单桌面／触摸 | 输入设备和响应式呈现 | 不应由页面随意挑选不同菜单行为 |
| 扫描运行小卡／完成大卡 | 布局状态 | 同一预览卡，容器改变列宽 |
| 182px／168px 菜单 | 历史不一致候选 | 不能为宽度差异发明 `home/library` variant |

**需要区分“已经存在的状态模式”与“应该新增的公共 variant API”。后者目前可以保持为空。**

# 10. Implementation Order

1. **先收敛普通电影卡及菜单的少量冲突决策。**  
   重点是菜单宽度、窄屏形态、更多按钮触摸／pressed 表现，以及来源详情菜单是否属于同一动作体系。只确认具体冲突，不重新设计页面。

2. **实现 MovieCard，并配套完成 MovieContextMenu。**  
   先覆盖同一电影在首页与片库的完整行为；不能只做 hover 海报，将更多菜单留给各页面复制。

3. **实现 Shell 级 GlobalSearchDialog。**  
   复用现有 AppSidebar 的搜索事件，补齐全局搜索；不新增第二套搜索入口或 Sidebar。

4. **迁移首页页面专属模块与 HomeShelf。**  
   保留原有四段顺序；最近观看使用独立剧照卡；只承接真实状态和首页已确定的自由滚动。

5. **迁移片库及四个个人视图。**  
   创建 LibraryToolbar、功能域空状态与 Skeleton；网格继续用 CSS；主片库再加入独立 CollectionCard。

6. **迁移电影／合集详情。**  
   复用普通电影卡与菜单；补当前电影状态；保留详情自己的 Hero、演职员和 Shelf 意图。

7. **迁移来源 → 扫描 → 匹配。**  
   随实际页面抽 SourceStatus、ScanHistoryItem、MoviePreviewCard；表单和确认任务保持各自职责。

8. **迁移 AI 页面。**  
   普通起始卡复用 MovieCard，推荐条目独立；不把 AI 理由、资源检查和会话状态塞进普通卡。

每阶段验证应包含同一内容／视口／状态下的 HTML–Vue 对照，以及键盘、触摸、快速开关、焦点归还和减少动效。构建成功不能替代这些检查。

# 11. First Component Recommendation

**是，下一步第一个最值得实现的组件仍然是 `MovieCard.vue`。**

原因是它同时具备：

- 五个片库页面完全一致的现成实现证据。
- 首页立即需要的两个使用区域。
- 合集成员、详情系列、AI 起始卡和来源详情的后续复用价值。
- 清楚的语义边界：一部电影的浏览与动作入口。

但首个交付目标应是**“MovieCard＋配套 MovieContextMenu 的完整行为”**，不能把菜单定位、状态反馈和焦点逻辑重新散落到页面。

先完成第 8 节与它直接相关的冲突确认；无需先创建万能 IconButton、通用 Overlay 框架或全局 MediaShelf，也无需先实现完整 HomeView。
