## 2. 建议删除：Custom Keyboard

| 文件 | 代码/区域 | 当前用途 | 是否影响 Mouse | 删除后的 Desktop 行为 |
|---|---|---|---|---|
| `components/media/MovieContextMenu.vue` | 第 108 行：onKeydown、document keydown、Arrow/Home/End/Tab/Escape | 手动菜单导航和关闭 | 不承担鼠标操作 | 鼠标点击、outside、resize、scroll 保留 |
| 同上 | 第 28、133、180、223 行：keyboardInput、pointerdown 重置、data-keyboard、条件焦点 CSS | 追踪输入方式、控制键盘高亮 | CSS 与 hover 共用规则，不能整行删除 | 保留 hover，移除键盘状态管理 |
| 同上 | 第 64、92 行：打开聚焦首项、关闭归还触发器 | 手动焦点管理 | 鼠标操作也会执行，但不是动作成功的条件 | 菜单照常开关，不再程序化移动焦点 |
| 同上 | 第 158、170 行：focusin → onOutside | 焦点移出时关闭 | 鼠标 outside 已由 pointerdown 处理 | 删除 focusin 注册，保留 pointerdown 和处理函数 |
| `components/layout/AppSidebar.vue` | 第 48 行起：menuItems、首尾聚焦、onMenuKeydown、onEscape | 菜单焦点导航 | openMenu 同时由鼠标调用 | 简化函数，不能删除开菜单功能 |
| 同上 | 第 183、197 行：方向键绑定、菜单 keydown | 自定义键盘入口 | 不影响 click | 账号按钮点击仍切换菜单 |
| 同上 | 第 48、97、104 行：restoreFocus、closeMenu(true)、focusin | 归还焦点和焦点移出关闭 | 账号操作也调用相关函数 | 保留关闭和 notice emit，移除焦点副作用 |
| `App.vue` | 第 8 行起：noticeTrigger、activeElement、dismiss 时 focus | 提示关闭后归还焦点 | 不影响提示显示和关闭 | 保留 notice 状态及关闭按钮 |

必须同步处理：

- 两个菜单的 `tabindex="-1"` 当前依靠手动聚焦进入菜单项。移除自定义导航时一并移除这些属性，恢复 button/link 的自然 Tab 顺序。
- MovieContextMenu 的 `.context-action:focus { outline:none }` 不能在删除键盘样式后继续压掉原生焦点；应移除此覆盖，或保留简单 `:focus-visible`。
- 当前没有动态修改 tabindex 的完整 roving-tabindex 状态机；实际是“所有菜单项 -1 + 查询节点 + 手动 focus”，同样属于清理范围。

## 4. 可选保留：低成本基础能力

| 能力 | 建议与依据 |
|---|---|
| button、RouterLink、原生 click | 必须保留；浏览器基本操作不需要自定义键盘事件 |
| aria-label、expanded、controls、hidden、图标语义 | 保留；expanded 控制卡片展开视觉，controls 参与鼠标切换判断 |
| 两个菜单关闭态 inert | 保留声明式绑定；菜单 DOM 驻留并有退出动画，需防止隐藏控件继续可操作 |
| MovieContextMenu 同步设置 menu.inert=true | 可随自定义 Tab 关闭逻辑简化，保留声明式 :inert |
| 简单 focus-visible | 保留；无监听器和额外状态，成本很低 |
| MovieCard 第 107–109 行三条 :has(:focus-visible) | 建议保留；按钮默认 opacity 为 0，删除会让自然 Tab 聚焦到不可见的播放／更多按钮 |
| desktop reduced-motion | 保留 MovieContextMenu 第 241 行、MovieCard 第 115 行、AppSidebar 第 475 行中的桌面部分 |
| 移动专属 reduced-motion | 删除 Sheet translateX 修正；touch scale 删除后可移除对应 transform reset |
| 侧栏减少透明度、对比度、forced-colors | 已有纯 CSS，无额外交互状态，本轮建议不动 |
| LibraryView announcement + aria-live + sr-only | 低成本状态播报，不是键盘导航；建议保留，sr-only 的 overflow:hidden 不是滚动锁 |

`role="menu"/"menuitem"` 与 `aria-haspopup="menu"` 是一组语义声明，不应为了保留它们反向恢复高级键盘逻辑。若清理时采用普通按钮浮层语义，应成组调整；aria-controls、aria-expanded 和标签无需因此删除。

## 5. 需要确认的灰区

### 5.1 侧栏 ≤900px 顶部导航

相关区域：AppSidebar 第 448 行的横向顶部导航、隐藏资料库／设置和账号菜单下置；第 199 行 compact-navigation 补充入口；App 第 82 行 sticky 顶栏与取消主区左偏移。

这是原型窄屏结构转换，但当前同样服务于 Windows 非最大化窗口，没有触摸专用输入要求。建议本轮保留。若希望窄桌面窗口仍维持左侧栏，需先确认布局方向，再成组处理。

**单独删除 compact-navigation 会使 ≤900px 下资料库和设置失去入口。**

### 5.2 侧栏 ≤680px 图标导航

AppSidebar 第 463 行隐藏导航文字并调整图标，是手机风格的紧凑呈现，也减少桌面窄窗口占用。无法仅从代码认定不再需要，建议与顶部导航方案一起决定，不列入首轮确定删除项。

### 5.3 LibraryView 的 680 / 420 断点

| 断点 | 实际作用 | 判断 |
|---|---|---|
| 900px | 内容左右间距缩减、标题区域微调 | 桌面窄窗口适配，保留 |
| 680px | 进一步缩减左右间距、调整标题间距、固定三列 | 混合区域：间距有桌面价值；固定三列是原型窄屏密度选择 |
| 420px | 三列改两列 | 配套固定三列方案，不是触摸行为 |

不建议直接删除整个 680/420 块。如果选择所有桌面窗口统一采用 auto-fill，可以一起删除三列／两列覆盖，保留合理间距。只删 420 会让更窄窗口继续挤三列。

是否放弃原型窄屏固定列密度，需要用户确认；本次未代为决定。

## 7. 结论与审计时工作区

1. 明确 Mobile/Touch-specific：**5 个文件**——MovieContextMenu、MovieCard、AppSidebar、App、style.css，包含一个仅提供触摸 Token 的文件。LibraryView 不计入明确专用实现。
2. 自定义 Keyboard/Focus 逻辑：**3 个文件**——MovieContextMenu、AppSidebar、App。若计入 MovieCard 的纯 CSS 键盘视觉增强，则共 **4 个**。
3. 复杂度最高的是 **MovieContextMenu**，同时承载双端呈现、滚动锁、定位、键盘与焦点状态。
4. 清理后 MovieContextMenu、AppSidebar 会明显简化；MovieCard、App 局部简化。
5. 推荐范围内未发现无法拆开的高风险耦合，但必须保留鼠标定位／滚动保护，同步处理 tabindex 与焦点 CSS。侧栏窄屏结构存在耦合，不建议直接删除。
6. **可以进入代码清理阶段。** 首轮按明确范围处理，灰区保留；实际清理后需桌面鼠标与窗口尺寸回归验证。
7. 推荐先清理 **MovieContextMenu.vue**，随后 MovieCard，再处理 AppSidebar 和 App。
